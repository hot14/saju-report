# T-07 · 입력·시각 모름·계산 타이밍 설계 (U7·U8·I7·X6)

> 상태: open · 우선순위: **P1** · 담당 후보: UX(I18N 협업) · 예상: 0.5d+1h(CTO 승계) · 소스: ux-validation-report Q4~Q6·리스크 #6·#7 + X6 + 악마 A2·B3·B4 · GitHub: hot14/saju-report#1 연계
> Design Read: 6필드 폼의 마찰과 시각 모름 플로우의 결과 상태를 단일 확정안으로 문서화, with 카피 덱과 UX 권고의 불일치를 한 문서에서 해소하는 정합 설계.

## 배경

- `docs/input-and-unknown-time-design.md` 부재 [파일 확인]. CTO U7·U8·X6·I7이 전부 이 문서를 산출물로 지정했다.
- 불일치(X6): 카피 덱 v2 입력 화면에 성별 필드가 없고(대운 방향 계산에 실제 필요, Q4), 출생 도시는 "선택"으로 기재됐으나 UX Q5는 필수+자동완성 권고.
- 악마 A2(치명): 필드 누락 시 10일간 정체성 카드(1번 자산) 계산 자체가 불능. B3: "같은 생년월일 = 같은 결과" 약속의 위반 가능성(시간대·절기 경계). B4: 음력 토글이 카피 덱에 1줄로만 존재.
- 시각 모름 사용자의 무료 결과가 어떻게 달라지는지(시주 공백·신뢰도 표기)도 미정의(Q6, R5).

## 범위

- 할 것: 신규 `docs/input-and-unknown-time-design.md` 생성. (a) 성별 (b) 도시 (c) 시각 모름 결과 상태 (d) 계산 타이밍 상수 (e) 로케일 검증 규칙.
- 하지 않을 것: 카피 덱 v2 직접 수정(정합 주석은 COORD 인계 목록으로 명시).

## 수용조건

- [ ] 성별: 필드 유지 기본안 + 사유 마이크로카피("10년 주기의 방향을 계산하는 데만 씁니다" 계열) + 응답 옵션·계산 규칙 명시(선호하지 않음 응답의 계산 규칙 포함)
- [ ] 도시: 필수+자동완성 확정(또는 대안 결정 + 근거) + "현지 시각 보정에만 사용" 사유 문안
- [ ] 시각 모름 결과 상태: 시주 공백 표기 방식·신뢰도 표기·±40분 경계자 안내 카드·"다른 계산기와 왜 다른가" 카드(SajuRoot 이식 판정) 각각 확정
- [ ] 계산 타이밍 상수: 총 3~4초 상한·1초 후 스킵 노출·같은 입력 = 같은 시퀀스(P1) 기록
- [ ] th 불기 연도 가드: 서기(CE) 병기 라벨 + 1900~2026 범위 검증(I7)
- [ ] 음력 토글의 동작 규칙(변환 방식·검증) 1단락(B4)
- [ ] 시간대·절기 경계가 P1 약속을 위반하지 않는 조건 명시(B3: 계산 기준 시각 정의)
- [ ] 문서 em-dash 0건·상대 단정문 0건
