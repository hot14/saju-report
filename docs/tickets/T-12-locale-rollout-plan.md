# T-12 · 로케일 순차 오픈 계획 (U17 + I5·I8 편입)

> 상태: open · 우선순위: **P3**(출시 로드맵) · 담당 후보: I18N · 예상: 0.5d(CTO U17 승계) · 소스: ux-validation-report Q17 + 악마 C1·C2·C3 · GitHub: hot14/saju-report#1 연계
> Design Read: 이미 검증된 10-로케일 조판 자산을 출시 순서 계획으로 전환하는 로드맵 문서, with 악마 게이트의 국가·법·지불 현실 지적을 계획의 검증 축으로 승계.

## 배경

- concept-guardrail §7 "10 로케일 1차 지원"과 실행 현실(폰트·법·지불)의 간극이 Q17. i18n-spec §1은 티어를 정의했으나 출시 순서는 "실측 후 판정"으로 열려 있다.
- 악마 C1(치명): ru-RU의 "지불 인프라 양호"는 2026년 현재 사실이 아니며 힌디 배제에 근거가 없다. C2: RTL 설계 0 + 아랍권 배제 결정 미기록. C3: 로케일별 법·지불 검증 축 부재.
- CTO 잔여 리스크 #4: 이 계획이 "10로케일 1차 지원 축소"로 오독되지 않아야 한다(조판 자산은 순차 활용, 폐기 아님).

## 범위

- 할 것: 신규 `docs/locale-rollout-plan.md` 생성. 출시 순서 + 재평가 트리거 + 악마 C1~C3 승계 축.
- 하지 않을 것: i18n-spec·multilang.css 수정. 신규 로케일 추가 번역.

## 수용조건

- [ ] 출시 단계: 1차 EN+KR 단일 → 2차 T1(ja·zh-Hans·en-GB) → 3차 T2·T3 순차, 단계별 오픈 조건(지표·검증 완료) 명시
- [ ] 재평가 트리거: 랜딩 실측(전환·결제 완료률) 기준의 단계 진입 규칙
- [ ] C1 대응: ru-RU 지불 현실 재검증 결과 반영(티어 조정 여부 포함) + 힌디 등 신규 로케일 후보의 근거 정리
- [ ] C2 대응: RTL(아랍권) 배제 결정의 명시적 기록(설계 0 상태의 고백 + 향후 조건)
- [ ] C3 대응: 로케일별 법(개인정보·면책)·지불 검증 축 매트릭스 추가
- [ ] "10로케일 자산은 순차 활용(폐기 아님)" 주석 포함(CTO 리스크 #4)
- [ ] I5(폰트 번들 병합 파이프라인)·I8(ja·zh 자형 렌더 QA)의 구현 단계 편입 위치 명시
- [ ] 문서 em-dash 0건

## 체크리스트

- [ ] 로케일별 지불 수단 현황 조사 결과 표(공개 자료 근거만)
- [ ] hreflang·URL 구조(i18n §2)와 출시 단계의 정합 확인
- [ ] 2차 오픈 로케일의 카피덱 확장 계획(T-03 구조 준용)
