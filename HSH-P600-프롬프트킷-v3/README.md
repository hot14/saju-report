## 일괄 실행 (요약)
0. `node runner/preflight.mjs .` — 12항목 사전점검 (이미 원문이 주입되어 있어 바로 통과)
1. 실행 순서: P600 → [P601~P606 병렬] → G1 → P607 →(DP-1)→ P608 →(DP-2)→ P609 → P610 → P611 → P612 →(DP-3)
2. 각 프롬프트 파일 전문 + `01-공통계약-CC.md`를 병합해 LLM에 1회 제출한다. 응답은 반드시 최대 출력 토큰으로.
3. 응답 원문을 저장하고 `node runner/validate-handoff.mjs <원문.md> --id P6xx`로 검증한다. 통과 시에만 다음 단계.
4. 검증 통과분을 `state/P6xx-out.json`으로 저장하고, 다음 프롬프트의 `{{입력}}` 슬롯에 주입한다.
5. DP(의사결정 포인트)에서 체인이 정지한다. 사용자 승인을 `state/dp-responses.json`에 기록 후 재개. 자동 진행 금지.
6. P612가 아카이브 등록으로 체인을 종료하고, 이후 매주 P613 운영 사이클(계획-실적 갭·게이트 판정·트렌드 델타)이 리포트를 최신으로 유지한다.

상세 규칙은 `runner/RUN-가이드.md`와 `01-공통계약-CC.md`를 따른다.

## 각 프롬프트 파일의 구성 (동일 골격)
| 섹션 | 역할 |
|---|---|
| 헤더 | 소비자(누가 읽나)·모델 파라미터·출력 문서 형식 |
| [페르소나] | HSH 6요소 정의 (역할/책임/도구/프로토콜/상태/동적 파라미터) |
| [입력] | 주입 슬롯 테이블 + state 파일 참조 |
| [임무 S1~Sn] | 단계별 지시 + 최소 분량 계약 + 수용기준 + 금지사항 |
| [출력 문서 골격] | 응답자가 전부 채워야 하는 목차 스켈레톤 |
| [handoff 스키마] | 필드/타입/필수/검증자 테이블 |
| [품질 게이트] | 자체검증 체크리스트 (SEC-3에 보고) |
| [스킬 훅] | korean-quality-gate 호출 시점 (해당 프롬프트만) |
| [확장/실패] | 확장 포인트, 실패 프로토콜 |
