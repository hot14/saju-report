**가져오기 허용(관용 범위)**

**금지(불변)**

## 축 1. 서비스 분석

### 사주아이가 하는 방식

**상품 7종(전부 990원 단건)**: 출처: `sajukid-archive/README.md`, `tmp/chunks/20205-*.js` 컬렉션 설정:

| 상품 | 목적 | 유료 경계 | 재구매 장치 |
|---|---|---|---|
| saju(사주해설) | 자기 자신의 성격·운 총론 | 열람 시 츄르 1개 | 프로필별 N회 재구매(실측 22회 소비) |
| goonghap(궁합) | 두 프로필 조합 | 열람 시 1개 | 상대 프로필을 늘릴수록 조합 폭발(15회 소비) |
| daewun(대운) | 10년 구간 리포트(현재/과거) | 열람 시 1개 | 구간 선택 UI로 여러 구간 구매(5회) |
| new-year(신년운세) | 연도별 운세 | 열람 시 1개 | 연도 단위 신상품(연 1회 자동 리필)(3회) |
| love(연애운) | 연애운 + 일기 페이지 | 열람 시 1개 | 일기 형식 반복 소비처 |
| taekil(택일) | 날짜 선택 | 열람 시 1개 | 용건마다 재사용 |
| jamido(자미두수) | 오픈 예정 신규 축 | 미정 | 보관함에 잠금 탭으로 수요 예열 |

**가격 구조**: 4티어 패키지, 단가 990원 고정(`data/api/credit-history-parsed.json` pricing): 맛보기 1츄르 990원 / 초보 3츄르+냥1 2,970원 / 단골 5+냥2 4,950원 / 애착(BEST) 10+1츄르+냥3 9,900원. 할인은 없고 물량만 늘며, 보너스는 냥(채팅 화폐)으로 지급해 해설 단가를 지킨다.

**무료 장치**: 수다방(복냥이 채팅, 무료 수다권 매일 밤 11시 1장 자동 충전) + 오늘의 운세(다마고치형 뽑기). 로그인 유도 문구 "로그인하면 기기가 켜진다냥"(홈).

**실측 경제(본인 계정, 2025-12-29~2026-09-02, `data/api/credit-history-parsed.json` 재계산)**
- 츄르 유입 10회 총 44개 = 결제 표기 6회 24개(토스 2·카카오페이 4, +11/+3×4/+1) + 무표기 구매 4회 20개(2025-12-29~2026-01-13, 5개씩 4회 = 단골 패키지 [추정]).
- 소비 45개: 사주해설 22(49%) · 궁합 15(33%) · 대운 5(11%) · 연도별운세 3(7%).
- 냥: 획득 6회 +9(결제 보너스), 소비 5회 -5(채팅 3회 충전 1냥씩), 잔액 1. 츄르 잔액도 1로 대차 일치(총합 -1 검증 완료).
- 해석: 결제는 언제나 "소비 직후 잔액 0" 근처에서 일어난다. 패키지는 냥 보너스라는 별도 화폐로 재방문 습관만 산다.

**왜 효과적인가(설계 논리)**
1. 단일 단가 990원은 "결정 없는 결제"다. 상품 간 가격 비교라는 인지 부담이 없다.
2. 츄르 사전 구매는 결제와 소비를 분리해 결제 통증을 앞당기고, 소비는 즉시(클릭 1번) 만든다.
3. 냥 보너스가 결제를 무료 채팅 습관으로 되돌린다(돈 → 재방문 → 다음 소비).
4. 프로필 멀티(14명, 1월에 8명 집중 생성)가 궁합 33% 소비의 직접 원인이다. 프로필 추가 = 소비처 추가.
5. 소비 집중도가 높다. 사주+궁합이 82%. 대운·연도별은 후속 확장용이다.

### SajuRoot 적용 판단

- **채택: 990원급 단건 진입**: 무료 차트 뒤 첫 유료 상품은 단일 가격 단건으로. 상품별 가격표를 만들지 않는다.
- **변형 채택: 이중 화폐**: 츄르식 사전 충전은 잔액 0에서 막히는 순간 이탈을 만든다(실측: 유입이 항상 소비 직후). SajuRoot는 "결제 즉시 열람"을 기본으로 하되, 결제 보너스로 주는 재화는 해설 단가를 깎지 않는 무료 채팅/추가 열람권으로 변형한다.
- **채택: 프로필 멀티 = 소비처 확대**: 궁합 소비 33%의 근거. 단, v1은 자기 프로필 고정으로 두고 가족·친구 프로필은 궁합 상품 출시 시점에 연다.
- **변형 채택: 무료 습관 장치**: 수다방 밤 11시 자동 충전 대신, SajuRoot는 무료 차트의 "오늘의 한 줄" 같은 일일 재방문 고리로 변형(푸시·이메일 의존 없이 URL 재방문).
- **기각: 패키지 할인 프런트**: 단가 고정 원칙은 유지하되, 4티어 패키지 UI는 SajuRoot 상품 수(초기 1~2종)에서는 과하다. 1~2티어만.

## 축 2. 서비스별 구현 방법

### 사주아이가 하는 방식

**스택과 데이터 계층**(`sajukid-archive/README.md` 요약): Next.js App Router + Firebase Auth(카카오·네이버·구글·이메일) + Firestore(seoul) + PostHog/GA4/네이버 wcs + Cloudflare. 클라이언트가 Firebase ID 토큰으로 Firestore를 직접 읽고, 결제와 AI 생성만 서버 API가 담당한다.

**Firestore 스키마(8종, 전부 검증)**: `users/{uid}/members/{mid}/` 하위에 sajuReadings·daewunReport·newYearFortuneReport/{year}·taekilReport·jamidoReport·loveReports·loveDiaryPages, 그리고 `users/{uid}/goonghaps`. 모든 생성물이 프로필 문서 하위에 종속되고, 프로필 삭제 시 해설이 동반 소멸한다(결제 45건 중 보관 잔존 사주 6·궁합 11·대운 10문서·신년 4문서, `README.md` 재검증표).

**상품별 데이터 흐름**: 입력폼(`/service/saju/add-new-member`: 이름·생일·시각·관계) → `members/{mid}` 프로필 생성(팔자 스냅샷 저장) → 결제 → 서버 API 생성(pipeline 상태 부착) → 보관함 목록 → `/service/saju/{mid}?readingId=` 재열람. 궁합은 member1/member2의 팔자+만세력 총량(member1_eightChars·member2_manseTotal 등)을 문서에 통째로 저장해 재열람 시 재계산하지 않는다(`data/firestore/goonghaps.json`).

**대운 파트 상태 머신(핵심 구현 패턴)**: `data/firestore/members/c2084f25-*/daewunReport.json` 실측:
- 문서 = report + periodReports + periodStatuses + fortuneData + tokenUsage + selectedPeriodIndex + periodType(current/past).
- periodReports 키는 구간 인덱스("4"). 한 구간 본문은 part2_coreAnalysis(3,361자) + part3_yearlyAnalysis(5,009자) + part4_closing(792자) = 9,162자, 3개 파트로 쪼개져 있다.
- periodStatuses = `{"4": {"part2": "completed", "part2StartedAt": …, "part3": "completed", "part4": "completed", "part4StartedAt": …}}`. 파트별 시작 타임스탬프와 상태를 함께 저장하므로 실패 지점부터 이어 생성할 수 있다.
- `report.freeOneLiner` = {title, description} 273자 무료 미리보기. 유료 본문 앞에 후킹 카드로 놓인다.
- fortuneData = bigFortuneList 10개(대운 10구간) + timeline 9개 + currentBigFortune(시작연도·위치·나이). 만세력 계산 결과를 원본 그대로 저장해 해설과 분리한다.
- 파이프라인 메타 {runId, status, lastRunAt, errorMessage}가 모든 생성물에 붙는다.

**REST API(12종, Bearer: Firebase ID 토큰)**: `README.md` 전체 재게시는 피하고 요지만: 프로필/궁합/잔액/채팅 세션·이력/purchase-status(7종 productId)/오늘의 운세/love-diaries 조회 + credits/use·nyang/exchange·generation/viewed·refunds 처리. 생성 결과의 "열람 시점(viewed)"과 "환불"이 API로 분리돼 있다는 점이 특징이다.

**보안 관찰(반면교사)**: 클라이언트 직접 Firestore 읽기 + 컬렉션 LIST 허용 덕에 본인 세션 토큰만으로 전체 데이터 덤프가 가능했고, 토큰은 localStorage에 평문 저장된다(`sajukid-990won-reverse.md` §6).

### SajuRoot 적용 판단

- **채택: 섹션맵 스키마 + pipeline 메타**: AI 해설을 프롬프트가 아니라 {한국어키: {title, description}} 섹션맵 + {runId, status, lastRunAt, errorMessage}로 저장. SajuRoot 무료 차트 결과 카드(S1~S12, `service/experiment/js/app.js`)를 같은 구조의 JSON으로 관리하면 부분 재생성·품질 검수·UI 재사용이 전부 열린다.
- **채택: 만세력/해설 분리 저장**: fortuneData처럼 계산 결과(computeChart 출력)와 해설 문장을 별도 필드로. 재해석 시 재계산이 없고, 해설 교체가 계산 무결성을 깨지 않는다.
- **변형 채택: 대운 파트 상태 머신**: S7 "시간의 흐름"을 대운 리포트로 확장할 때 그대로 채택(파트 3분할 + partN 상태 + 실패 재개). SajuRoot는 무서버(GitHub Pages)이므로 생성은 백엔드 함수가 아니라 "요청 시 API 라우트/함수 1회 호출 + 로컬 저장"으로 바꿔서.
- **채택: freeOneLiner 무료 미리보기**: 유료 본문 앞 {title, description} 한 장 무료 제공. 전환 후킹의 구현 원형.
- **기각: 클라이언트 직접 DB 읽기 + localStorage 토큰**: 자기 데이터 전체 덤프 사례 그대로. SajuRoot는 개인 데이터 조회를 서버 경유 API로만, 토큰은 httpOnly 쿠키로.
- **기각: 프로필 삭제 시 해설 동반 소멸**: 유료 결제 자산이 프로필에 종속되면 분쟁·이탈의 씨앗. SajuRoot는 해설을 유저 루트 컬렉션에 두고 프로필 참조만 저장.

## 축 3. 해설 작성 방식

### 사주아이가 하는 방식 (원문 정독 + 정량 분석)

근거: `data/firestore/members/c2084f25-*/sajuReadings.json`(사주해설 5건), `data/firestore/goonghaps.json`(궁합 11건), `data/api/chat-history/c2084f25-*.json`(복냥이 32메시지).

**구조(정량)**
- 사주해설 13섹션 고정, 각 섹션 {title, description}. 총 길이 5,696~7,560자(5건 평균 6,239자), 섹션당 412~566자(첫건 기준). 타이틀은 본문과 별개의 후킹 문장이다.
- 궁합 13섹션 + score(숫자) + title. 섹션당 670~962자, 총 10,169자. score 실측 68~92(평균 84).

**호칭·어미 공식(관용 범위에서 규칙으로 추출)**
- 호칭: 이름+님("김ㅂㄱ님")과 "당신"을 혼용한다. 5건×13섹션에서 이름+님 10회, "당신" 60회. 즉 기본 대명사는 "당신", 문서 전체에서 2~3회만 이름+님으로 접지(만남의 온도 조절).
- 어미: ~습니다 계열 117 vs ~어요 계열 94. 기본 존댓말이되, 해설 톤을 부드럽게 만드는 "어요체"가 45% 수준까지 섞인다.
- 이모지: 본문 0회. 이모지는 궁합 타이틀("🌊…🪴…", "⛰️💎") 같은 타이틀 라인에만 쓴다.

**타이틀 공식**(예시는 발췌+출처): `[반전·은유 후킹] + [의문(?)] + [당신의 ~]` 3요소. 예: "겉은 세상 차도녀인데 속은 거대한 호수? 당신의 반전 매력"(sajuReadings 레코드0 한마디로_표현하면). 궁합은 관계 밈체 허용: "애증의 마라맛 케미…", "톰과 제리 케미"(goonghaps 5·10번).

**대비 구조(핵심 감정 설계)**: 신랄한_비판과 따뜻한_위로와_칭찬은 항상 짝으로 존재하며, 같은 결함을 두 문장에서 반대로 읽는다. 비판은 사주 근거를 명시하고("원국에 토 관성이 없고 수 비겁이 강력하다 보니…", 레코드2), 위로는 같은 팔자를 보상 서사로 뒤집는다. 서두 신호어는 "솔직히 짚어드자면"/"하지만 김ㅂㄱ님, 저는 알아요"(레코드2·4). 규칙으로 바꾸면: 결함 지적 → 반드시 같은 지점의 강점 재해석으로 종료.

**개운법 삽입 공식**: 전용 섹션이 없다. 원소 부족 진단이 파생 섹션(지역·직업·성격) 안에서 색상(7회)·방위(5회)·행동 처방으로 자연 녹는다. 사용자가 직접 언급한 금생수 같은 케이스는 concern 반영 경로로 들어간다(레코드3 "물어보신 금을 쓰는 직업이란…").

**concern(고민 프리텍스트) 반영**: 입력은 선택(300자 제한, `clone/saju-input.html` "현재 상황이나 고민 (선택)"). 반영 방식이 극단적으로 깊다. 레코드3(입력: 글쓰기·금생수·육아)에서 한마디로_표현하면이 "두 아이를 키우며… 거대한 에너지를 가두어 두고 계셨어요", 직업이 "물어보신 금을 쓰는 직업이란…"으로 입력 내용을 그대로 문맥화한다. 무료 입력 1줄이 전체 해설의 개인화 밀도를 결정한다.

**궁합 점수 산출 설계**: 점수는 숫자 필드(score)와 서술(궁합점수 섹션)이 분리돼 있다. 서술은 근거를 명시한다: "이러한 점수가 나온 가장 큰 이유는 두 분의 지지(地支) 구성에서 찾아볼 수 있습니다…(goonghaps 0번)". 관계 라벨 6종(친구 5·배우자 2·모녀·모자·딸과 엄마·직장동료)이 섹션 톤을 바꾼다.

**복냥이(채팅) 톤**: 반말+이름+님 혼용("김ㅂㄱ님, … 아니야/거든/구나"), 이모지 0, 답변 평균 1,081자(최대 1,315자). 1세션 = 유저 1질문 + 봇 1답변 = 수다권 1장. 첫 답변에 정체성 스크립트("나는 사주아이의 전속 상담사 복냥이야…", 세션0)를 붙이고, 상담 본문에도 월별 세운 표를 근거로 제시한다. 제안 질문 칩("오늘 일 풀리는 흐름 맞아?")이 다음 세션 소비를 겨냥한다.

**비결정성 관찰**: 유저가 채팅에서 확인한 바, 같은 명식 재생성 시 "처방도 다른 경우"(chat-history 유저 발화 15통째)가 있다. 즉 템플릿 골격은 고정이지만 생성은 매번 샘플링된다 [추정: 완전 고정 프롬프트가 아니라 온도 부여].

### SajuRoot 적용 판단

- **채택: 13섹션식 고정 골격 + 후킹 타이틀**: SajuRoot의 S1~S12 고정 순서와 정확히 같은 사상. 각 섹션에 {title, description}을 부여하고 타이틀 공식(후킹+의문+당신)을 적용한다. 단 공식 적용, 문구 복제 아님.
- **채택: 대비 구조(쓴소리→보상 종료)**: 조심할 신호(S6) 섹션의 서두 신호어 규칙과 "같은 결함의 강점 재해석으로 종료" 규칙을 그대로 채택.
- **변형 채택: concern 프리텍스트**: 무료 차트 입력폼에 고민 1줄(선택, 300자)을 추가하고 결과 파생 섹션(직업·시간)에 문맥화 반영. SajuRoot는 정적 계산만 있어 반영이 어려우므로, 반영 지점을 "표시 로직"으로 변형(고민 키워드와 매칭되는 섹션 강조 + 한 줄 맞춤 코멘트).
- **변형 채택: 호칭·어미 밴드**: 이름+님 2~3회 접지 + "당신" 기본, 존댓말 기본에 어요체 40~45% 혼용, 본문 이모지 0. 밴드 값은 사주아이 실측값을 기준선으로 삼되 남촌 물상 언어로 새로 쓴다.
- **채택: 궁합 점수 근거 서술 분리**: 점수(숫자)와 근거 서술 분리, 지지 구성 기반 설명 방식.
- **기각: 복냥이 캐릭터·카피 모방**: 페르소나 채팅은 상품 단위 투자다. SajuRoot 초기 스코프에서 제외하되, "1세션=1재화, 제안 질문 칩" 구조만 기록해 둔다.

## 축 4. 구성

### 사주아이가 하는 방식

**보관함(library) 4층 정보 구조**(`clone/library.html` 실측 스크린샷):
1층 프로필 탭: 원형 아바타 가로 스크롤(+추가 · ALL전체 · 개인 7명), 대표 프로필 배지.
2층 서비스 탭: 만세력 / 별자리(잠금) / 자미두수(잠금) / 베딕(잠금). 미출시 축을 잠금 아이콘으로 노출해 수요를 예열한다.
3층 선택 프로필 카드: 아바타+대표 배지+이름+생일 정보, "나의 사주 명식" 4×2 컬러 타일 그리드 + "전체보기 >".
4층 유형 필터 칩(전체/사주해설/궁합/대운세션/연도별 운세) + 날짜 정렬 아이템 목록(행별 삭제 버튼).

**화면 흐름(전환 설계)**: 홈 운세뽑기(무료, 다마고치) → 로그인 → 수다방(일일 무료 수다권) → 해설 상품(입력폼 → 결제 → 리딩 뷰) → 보관함. 보관함은 소비 이력의 저장고이자 재열람·재구매의 분기점이다.

**결제 흐름**: 코인상점(/payment) 4티어 리스트 → 토스/카카오페이 → 츄르·냥 반영(상단 배지 실시간 표시) → 열람 시점 credits/use → generation/viewed로 열람 기록 → 실패 시 refunds API.

**데이터 정리 구조의 함정**: 아이템 삭제가 행 단위가 아니라 프로필 단위 폭포로 설계돼 있다. 실측에서 결제 45건 중 보관 잔존이 사주 6건뿐인 것은 삭제된 프로필의 자식 문서가 함께 사라졌기 때문이다(`README.md` 재검증표).

### SajuRoot 적용 판단

- **채택: 4층 IA(프로필→서비스→필터→목록)**: SajuRoot가 결과 저장소를 갖게 되면 같은 4층 구조를 기본형으로. 필터 칩과 날짜 목록, 행별 삭제는 그대로.
- **채택: 미출시 기능 잠금 탭**: 별자리·자미두수·베딕 잠금 탭은 개발 로드맵 공개 장치로 저비용·고효과. SajuRoot 로드맵(대운 확장, 궁합)에 동일 적용.
- **변형 채택: 열람 시점 기록(viewed)**: 생성/열람/환불이 API로 분리된 설계를 참고해, SajuRoot도 "생성 완료"와 "사용자가 열었음"을 분리 기록(무료 단계에서는 localStorage 이벤트 로그 수준).
- **기각: 프로필 단위 삭제 폭포**: 유료 자산 보호 관점에서 채택 불가. 삭제는 아이템 단위 기본, 프로필 삭제 시 자산 이관 확인 대화상자.
- **기각(보류): 수다방 중심 일일 습관**: 채팅 인프라 없이는 재현 불가. 대체재는 축1의 "오늘의 한 줄" 일일 고리.

## 축 5. 레이아웃

### 사주아이가 하는 방식 (`clone/*.html` 스크린샷 실측)

**공통 프레임**: 모바일 중앙 정렬 단일 컬럼(최대 약 448px), 크림/아이보리 배경, 라운드 카드. 상단 헤더는 좌측 로고 + 우측 잔액 배지(츄르 0 / 냥 1 상시 노출) + ? + 햄버거. 하단은 플로팅 필형 탭바(홈/수다[배지]/클로버/프로필)로 콘텐츠에 겹쳐 뜬다. 결제 재화가 "브랜드 UI"가 아니라 잔액 배지라는 점이 특징이다.

**해설 상세(reading-saju.html)**: 노랑 상단바(뒤로 + "김ㅂㄱ님의 사주해설" + 생일 칩 5개) → 만세력 밴드(오행별 색상 타일 4×2 그리드 + "자세히 보기") → 사주해설 밴드("각 섹션을 클릭하면 해설이 펼쳐져요") → 아코디언 섹션 13개(타이틀+케밥+펼침). 스크롤 유도 플로팅 힌트("아래로 스크롤해주세요")와 공유 FAB가 떠 있다. 6,000자 분량을 아코디언으로 접어 심리적 분량 부담을 제거한다.

**입력폼(saju-input.html)**: 질문형 상단 배너("요즘 어떤 점이 가장 궁금하신가요?") + 개인화 문맥("김ㅂㄱ님의 사주를 보고있어요") + 고민 프리텍스트(선택, 0/300 카운터) + 핑크 CTA("사주 해설 보기") + 저항 완화 링크("입력 없이 바로 보기").

**결제(payment.html)**: 티어 리스트(맛보기/초보/단골/애착 BEST) + 보너스 냥 표기 + 구성 수량 강조. 가격 비교가 아니라 "캐릭터 있는 티어명"으로 감정 소구한다.

**오늘의 운세(fortune-daily.html)**: 핑크 깅엄 배경의 다마고치형 "Fortune Catcher" 기기 + "버튼 눌러서" 뽑기. 운세를 콘텐츠가 아니라 장난감으로 패키징한다.

**수다방(chat-boknyang.html)**: 페르소나 헤더(고양이 사진 + "35년 사주 전문가 해설도사의 수제자") + 잔여 재화 칩("쿠폰 1/1", "남은 수다 2회") + 유저 핑크 말풍선 / 봇은 노트 스타일 카드(월별 세운 예보) + 일반 말풍선 혼합 + 제안 질문 칩 + 페르소나 전환 콤보("너 · 김ㅂㄱ ▾ + 궁금한 사주 추가하기").

**viewer.html**: 모든 해설의 렌더링 예시 단일 파일. 섹션맵을 카드 나열로 렌더하는 뷰어 패턴(아카이브 도구지만 UI 패턴 학습 대상).

### SajuRoot 적용 판단

- **채택: 아코디언 리딩 뷰**: 장문 해설(6,000자급)의 표준 렌더. SajuRoot 결과 카드에 "섹션 클릭 펼침"을 적용하면 현재 스크롤 폭포 문제가 사라진다. FAQ details 패턴(`faqSection`)과 병합.
- **채택: 잔액·재화 배지 상시 노출**: 유료화 시 헤더 우측에 보유 재화 배지를 상시 노출해 결제 필요성을 문맥에 붙인다.
- **변형 채택: 만세력 컬러 타일**: 오행별 색상 매핑 개념은 Swiss Ledger 토큰(v1.0)의 검정 단색 체계에 맞게 변형(색상 대신 오행 글자 + 밀도 도트). 현재 `edots` 오행 도트가 이미 같은 아이디어의 축소판.
- **변형 채택: 플로팅 필형 하단 탭바**: 모바일 전환 시 현재 foot-links 대신 필형 탭바로. 데스크톱은 유지.
- **기각: 다마고치·캐릭터 의존 장치**: Fortune Catcher, 복냥이 아바타는 캐릭터 IP 투자가 전제다. SajuRoot는 캐릭터 없는 게이미피케이션(스탬프·연속 일수)으로 대체.
- **기각: 448px 고정 단일 컬럼**: SajuRoot는 데스크톱 우선 Swiss Ledger 그리드를 유지. 모바일에서만 단일 컬럼으로 수렴.
